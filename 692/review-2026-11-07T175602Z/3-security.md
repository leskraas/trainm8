# PR #692 — Security (by hand; security-review skill not run: report-only by hand per review-pr step 1.3)

Checked: authorization/IDOR, injection, secrets, unauthenticated surface, CSRF, SSRF, data exposure. No new route, loader, action or query; the e2e posts to the existing `/imports/upload` as the logged-in test user. No secrets.

X1 (low, verified). Unbounded server memory via the formatter cache. `app/utils/athlete-calendar.ts:27-43` keys `FORMATTERS` on the raw timezone string. The comment says "The set of timezones is bounded by IANA", but Intl accepts any letter case: `node -e` shows `europe/oslo`, `EUROPE/OSLO` and `Europe/Oslo` all resolve to `Europe/Oslo`, each a distinct key. The stored Athlete Timezone is only `z.string().min(1).max(100)` (`app/utils/athlete-schema.ts:104`), so a user who keeps rewriting their timezone in new casings grows the server's process-lifetime Map by up to three formatters per variant, never evicted. Scenario: script profile updates cycling case variants of `America/Argentina/ComodRivadavia` (2^30+ variants), each followed by a page load. Fix: key on the lower-cased zone (outputs are digits and do not depend on the input's case). The same pattern pre-exists in `nbParts` (`app/utils/format.ts:283`, base branch) — follow-up, not this PR's.
