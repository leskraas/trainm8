Motion

Four animations survive. Five were rejected.

A screen the athlete opens every day argues for less motion, not more. Everything here passed a gate on frequency, then had to name its purpose in one word.

What animates

ElementPurposeIngredientsCurve
Empty cell → editor State height + opacity 200ms ease-out
Past band → expanded Jarring height + opacity 200ms ease-out
Row & cell press Feedback scale(0.97) 160ms ease-out
Back-to-today pill Jarring opacity + translateY(8px) 200ms ease-out

height is the sanctioned exception. Both accordions genuinely reflow their neighbours, and no transform does that — which is exactly the case the rule carves out. It costs layout every frame, so both stay at 200ms and neither goes longer.

The pill enters from the bottom edge it lives on and leaves the same way. A surface that arrives one way and departs another reads as two different things.

The hero collapse is not an animation

It fires every time the athlete crosses the threshold, on the screen they open most — which puts it in the tier where the answer is “reduce or remove”, not “pick a better curve”. So it stops being a 280ms transition and becomes scroll-driven: collapse progress reads directly off scroll offset, 1:1, with no duration at all.

That also removes the reason the four timing ladders exist. Feedback during a gesture should be continuous, not a transition that fires once the gesture is over.

The two gestures

Hero — pages

Spring, bounce: 0, duration: 0.35. Critically damped, because a deliberate swipe carried no momentum to pay back.

The landing pane comes from projecting the flick, not from where the finger let go:

current + (v/1000)·d/(1−d)
d = 0.998

Strip — scrolls

Native overflow scroll with proximity snap, as today. No spring: it is a scrubber, not something you throw.

At the season’s ends it rubber-bands rather than stopping dead — resistance rising with overshoot:

(over · dim · 0.55)
/ (dim + 0.55·|over|)

Release velocity hands off to the spring so there is no seam between dragging and settling. motion@12.38 is already a dependency, so neither needs a new one.

The strip glide is the one worth arguing about. It is the only way to cross a season quickly, but six months of smooth scroll is a long animation on a repeated action — so it jumps, and the strip’s own re-centring is what shows you moved.

What to add

The repo has --animate-* keyframe tokens but no easing scale, so these are new rather than a second system beside an existing one. Built-in CSS easings are too weak to read as deliberate.

--ease-out: cubic-bezier(0.23, 1, 0.32, 1); --ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);

Reduced motion ships with the animation, not after it. Gentler, never zero: keep the opacity halves, drop the transforms and both smooth scrollers. The repo already writes motion-safe: in the token popover and the block-editor sheet, so the timeline is the outlier.

Hover motion goes behind @media (hover: hover) and (pointer: fine). Press feedback does not — :active is a real press on touch.
