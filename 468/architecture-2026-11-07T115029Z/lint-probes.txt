1. Does a second `no-restricted-syntax` block for app/** and server/** shadow the
   route-file `<select>` guard in eslint.config.js?

   Ran: a throwaway config that spreads eslint.config.js and appends
   { files: ['app/**/*.{ts,tsx}','server/**/*.ts'], rules: { 'no-restricted-syntax': [user.delete selector] } },
   then `npx eslint -c <probe> --print-config app/routes/settings/profile/index.tsx`.

   Effective rule on the route file with the probe config:
     [2, {"selector":"CallExpression[...user...delete...]","message":"Use deleteAccount"}]
   Effective rule with the shipped config:
     [2, {"selector":"JSXOpeningElement[name.name='select']", ...}]

   Showed: yes. Flat config replaces a rule's options per matching block; it does
   not merge them. Whichever block comes last wins, so adding the new rule as its
   own block silently drops the native-<select> guard on every route file (or the
   reverse, depending on order). Both restrictions must be listed together in the
   block that covers route files.
