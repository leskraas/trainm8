The Week Pattern picker offers the saved list

leskraas/trainm8#666 · design canvas · run 1 · phase poc · one variant (unattended)

Recommended: Grouped picker run 1 6 decisions two-way door

The add-a-day form on a run track, Økt open at 390 px: the athlete's recent own Workouts, then the ones they saved in the Catalogue. "Langtur 18 km" is in both lists and shows once. The live version is the next board.

Grouped picker Chosen
Axis: interaction model Same one Select as today, two labelled groups inside it. No new control.
Gain A saved Workout is one tap away, in the control the athlete already knows; nothing to learn, nothing new to build.
Cost With a long saved list the popup gets long (no search, out of scope); the group label is the only provenance shown.
Criteria held 9 of 9 hold as far as a drawing can show; 2, 3, 4, 6 and 9 also need the server guards, which are the build's
Worst case Holds at 320 px, in dark mode, and with emoji, Cyrillic and one-word titles. In the real Select, a 120-character title is clipped (whitespace-nowrap, select.tsx:139), and 71 options bury the saved group. The build fixes both
Build cost small: __week-pattern-editor.tsx (groups via the existing SelectGroup/SelectLabel), labels/sesong.ts, the loader read and addWeekPatternDay's guard. No new dependency or component.

Decisions

  • A Workout in both lists appears where? → once, under Dine siste økter.
  • A group with nothing in it? → not shown; one non-empty group still carries its label.
  • Group labels in a long list? → sticky at the top of the popup, so the group in view is always named.
  • Long titles in the popup? → wrap to as many lines as they need; the closed trigger truncates with an ellipsis.
  • Empty state's Catalogue link? → /training/catalogue?discipline=<track>, filtered to the track's sport.
  • The "workout gone" wording, now that a gone Workout may never have been the athlete's? → reworded to Den økta er ikke lenger tilgjengelig. Velg en annen økt for denne dagen.

Designer's pick

Method

Tool: Emil's prototype (standalone branch), since the issue asks what a picker and its empty state look like and the run is unattended. Its prototype-ui skill folder (SKILL.md, PICKER.md) is not installed in this environment, so the prototype follows its stated output instead: one self-contained HTML file in trainm8's own tokens (app/styles/tailwind.css, Public Sans embedded), with the repo's emil-design-eng, apple-design, mobile-native and break-ui skills as the bar. The component mirrors AddPatternDayForm in app/routes/training/__week-pattern-editor.tsx and the luma Select (44px items on a coarse pointer, motion-popup 200/150ms from scale 0.96). Base UI aligns the open list over the trigger; the prototype drops it below, which changes nothing the groups decide. Copy is drawn from SESONG_PATTERN_LABELS; new and changed strings are listed in the issue's Design section.

Rejected directions

  • A segmented control above the picker (Mine · Lagret): a second choice before the real one, and a fixed day would open on whichever segment is empty. Not drawn (poc: one variant).
  • A second Select for the saved list: two fields for one value; which one wins when both are set is a rule the athlete has to learn.
  • A searchable combobox: search is out of scope; it is where a long saved list goes next (see Debt).

Grouped picker Chosen

The Avansert pattern card at phone width with the issue's real cases: a run track with recent and saved Workouts (one in both), a bike track with only saved ones, a swim track with neither. Pick a day and add it; tick the box to have the saved Workout retired between opening and submitting.

Worst case

break-ui's data through the same boundary as the demo: 12 recent own run Workouts (the cap) and 60 saved ones, a 120-character title (the schema's max), one-word, emoji and Cyrillic titles, the same title in both groups under different ids, a bike track with only one recent Workout, and the zero and one cases.
